# mtluntan 1.1.2 更新说明

> 本轮针对你反馈的 7 条逐条处理。源码 + **只发 release 安装包**（本版不再附带 debug 包）。
> 构建（含单元测试）与打包全部在本地沙箱完成，未使用 GitHub Actions。
> 另外附一份 `mapping-1.1.2.txt`（R8 混淆映射），只用于把崩溃栈里的混淆帧还原成真实类名，不是安装包。

## 1. 以后只发 release 安装包
- 发布附件只给 `mtluntan-1.1.2-release-debugsigned.apk`（release + R8 混淆 + 资源压缩）；
  上一版一起发的 debug 包不再发布（`versionCode 4 / versionName 1.1.2`）。
- 沙箱里没有你的正式 keystore，所以这个 release 包仍用 debug 签名 —— 与你之前安装的 1.1.1 是同一签名，
  **可以直接覆盖安装，不会掉账号**。

## 2. 多账号：不再「加一个删一个」，而且显示账号信息
参考 `yz8023/mt-lun-tan` 的 `AccountManager` 设计（每个账号一份**完整 cookie 快照** + 各自的活动指针）重写导入链路：
- **根因**：以前账号名是从页面 `<title>` 里取的，而论坛所有个人资料页标题都是「个人资料 - MT论坛」，
  于是新账号算出来的名字和上一个一样 → 被当成同一个账号覆盖掉。现在**不再从标题猜名字**：
  用户名只取 `.comiis_space_tx h2`、用户组、头像、用户 ID 等真实字段，并经过 `sanitizeUsername()`
  过滤（长度 ≤24、拒绝「论坛 / 登录 / 注册 / Powered / 纯数字」这类噪声）。
- **uid 兜底**：`findUid` 只认 `uid > 0`，并新增脚本级兜底 `findUidInScripts()`（`discuz_uid='123'` 等），
  另有 `looksLikeLoginPage()` 判定「这是登录页不是身份页」，避免把登录壳当成账号。
- **撞名不再覆盖**：同名但 uid 不同时，新账号自动改用 `uid_<uid>` 作为键保存，两个账号都在。
- **认不出身份就问**：`ImportOutcome` 分 `NeedName` / `Ok(username, isNew)`，认不出就弹「给这个账号起个名字」，
  而不是伪造 `uid_0` / `account_时间戳` 这种假账号。
- **账号内容信息可见**：账号表新增 `用户组` 列（Room v3 → v4 迁移，老数据不丢），
  身份解析走三级兜底（手机版资料页 → PC 版 `home.php?mod=space&do=profile` → 内联 `discuz_uid`，带重试）。
  账号卡片现在显示：显示名 + 当前账号徽标 + 可能掉线提示 + 用户名·UID·用户组 + 积分 + 签到天数/连续/排名。

## 3. 评论区：滑到底自动拼接下一页；标记清楚；间距收紧
- **自动加载**：`LazyColumn` 监听最后一个可见项，距底部还剩 2 条时自动拉下一页并**追加在下面**（不跳页、不重开）；
  底部仍留「加载更多」兜底按钮和「没有更多了」结束提示；开关仍是设置里的「评论自动下一页」。
- **每条分明**：每个楼层左侧一条**楼层色条**（楼主=主色、回复=次要色），头部一个 `#12 楼` 徽标，
  配作者 / 用户组等级 / 时间；「回复 @某人」单独一行；楼层之间加细分隔线。整条评论从哪到哪一眼可见。
- **间距**：楼层卡片内外边距 12→10、卡间 4→3，动作行由 48dp 的 `TextButton` 换成小胶囊（支持 / 回复 / 更多），
  评论区整体高度明显下降。
- **主页/版块列表**同样改成滑到底自动拼接下一页（上一版只有「加载更多」按钮）。

## 4. 快捷工具栏：文字 / 图标可切换，行数可自定义（默认两行）
- 新增设置项 **「快捷工具栏形态」= 文字 / 图标**、**「工具栏显示行数」= 1~4 行（默认 2 行）**；
- 12 个动作（加粗/斜体/下划线/代码/引用/隐藏/颜色/渐变字/链接/图片/标签/编辑器）按行数**自动等分**，
  末行补空位，按钮宽度一致、不滚动、不再挤成一条；
- 发帖编辑器与帖子页回复面板共用同一套 `BbcToolbar`，改一处两处都生效。

## 5. 帖子列表排版
- 标题用 `titleLarge` 加粗、最多两行，**明显放大突出**；
- 标题下方一行小字：发布人 · 用户组/等级 · 时间 · 回复/查看；
- 正文摘要中号字（最多三行）；
- 图片作为**缩略图放在正文下面**，最多 3 张、按数量自动决定高度，**没有图片就完全不占位**（不再有空白方块）；
- 板块 / 精 / 顶 / 回复可见等标签在最下面一行，用系统标签解析到的等级（解析不到就不显示，不瞎填）。

## 6. 主页翻到底自动加载并直接拼接
- 见第 3 条：主页导读、版块列表、评论区三处的分页都改成「滚到底自动接下一页 + 直接拼接」，
  到底显示「没有更多了」。

## 7. 评论区点击闪退（`ArrayIndexOutOfBoundsException: length=0; index=-5`）
这次拿到了你的崩溃帧（`l0.r.t…`），用 **1.1.1 源码在本地重建了一次 release 并比对 `classes.dex` 哈希
（与线上包完全一致）**，因此拿到了准确的 R8 mapping，还原出一手结论：

```
l0.r   = androidx.compose.runtime.ComposerImpl
l0.r.t = ComposerImpl 的组结束方法（内联了 SlotWriter.getParent / groupKey / groupAux、
         SlotTableKt.key(int[],int) / groupInfo(int[],int) —— 全是 SlotTable 的「组结构」记账）
```

也就是说：这不是我们解析数据时的普通数组越界，而是 **Compose 运行时的组合「组结构」错位**。而本工程里
最典型、社区里最容易触发它的写法就是 `Modifier.composed { … }`（Google 后来废弃 `composed` 正是因为这个）：
`pressScale` / `impactShake` / `mtSpecular` 三个动效 Modifier 全用它，而它们挂在**每一个卡片和每一个楼层**上，
列表项一被复用，那个「延迟到布局阶段才跑的小组合」就可能错位。

**修复与加固**：
- 三个 Modifier 全部改成普通的 `@Composable Modifier 工厂函数`（效果完全一致，代码注释里留了原因），
  工程里已无 `Modifier.composed`；
- 楼层列表的 `key` 由 `pid` 改成 `pid>0 ? "p$pid" : "i$index"`，杜绝 pid 解析不到时的重复 key；
- 全屏看图 `ImageGallery` 的下标全部夹紧（空列表 / 变短 / 起点越界都不再越界），
  并去掉了「在组合期间写状态」的写法；
- `parseColor` 的颜色解析加上十六进制校验（`#12g` 这类脏数据不再抛异常）；
- 新增 **崩溃记录器**（设置 → 关于 → 「崩溃日志」）：崩溃瞬间把完整堆栈、线程、版本和运行日志尾部
  写进本地文件，可在设置里查看 / 复制。万一还有闪退，把那段日志发我即可（配合 `mapping-1.1.2.txt`
  可以还原到具体类名与行号）。
