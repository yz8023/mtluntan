# mtluntan 1.1.3 更新说明

> 本版针对你反馈的 10 条逐条处理，**只发 release 安装包**。构建与打包在本地沙箱完成（未使用 GitHub Actions）。
> 附件里的 `mapping-1.1.3.txt.gz` 是 R8 混淆映射，只用于把崩溃栈还原成真实类名，不是安装包。

## 1. 评论区翻页：整页切换，不再拼接（改回你要的方式）
上一版把下一页**拼**到当前页，结果翻过去就回不来了。现已改回：**评论按页翻**——
- 滚到底**不会**自动把下一页接上，当前页只显示这一页的回复；
- 评论区有一条**吸顶翻页条**（「上一页 · 评论区 第 x/y 页 · 下一页」）：不管滑到哪一层，它都贴在屏幕顶部，随时能翻回上一页（这次「回不去」的真正原因就是翻页后列表跳回顶部、而翻页条只在最底部）；
- 页尾再放一条同样的翻页条，读完这页可以顺手翻；
- 底部还有整页页脚提示「第 x / y 页（整页切换，不会拼接）」。
- 顺带把设置里原来那条「评论自动下一页」改名为 **「自动解锁后续页」**（只影响后台找隐藏内容并解锁，与显示无关）。

## 2. 正文图片 + 正文与评论区的区分
- **正文图片丢失的真正原因**（两个叠加）：① 站点正文图是**懒加载**，真地址在 `file`/`data-original`/`data-src`/`zoomfile` 上，`src` 只是 `none.gif` 占位图，旧代码只读 `src` → 图全变占位图；② 上一版把表情和配图混在一起后，配图又被当表情过滤掉。现在：
  - `[img]` 标签图；
  - 正文里的裸 `<img>`（`<br />` 独立成行的也算正文配图）——`ThreadItem.images` 现在会合并两者；
  - 表情（smiley）仍然被排除在外。
- **正文和评论区分开**（并按你给的 dyparse 应用底部栏那种风格）：
  - **楼主/正文**：整宽卡片 + 顶部**主题色渐变头带** + 「楼主」徽标 + 正文前一行「正文」标记 —— 一眼看出这是主帖；
  - **每条评论**：右侧缩进的**半透明气泡**（玻璃质感 + 按下缩放反馈），一条评论就是一个气泡，跟正文完全不同层；
  - **删掉了左边那条竖色条**（你说的「不要每条评论左边加一个条」，已去掉）；
  - 楼层之间不再画横线，靠气泡的层次和间距区分。

## 3. 论坛自带表情被当成图片
- 新增统一的**表情识别**（`static/image/smiley`、`/smiley/`、`/face/`、以及 `sad.gif`/`biggrin.png` 这类纯文件名表情）；
- 正文解析时表情**不再生成 `[img]`**，而是按站点自己的记法显示成 `[憨笑]` 这样的文本；
- 图廊（点开大图）**只收正文配图**，所以点表情不会打开一张不相干的图；
- 点击图标改为**按 URL 定位**（点哪张开哪张），不再用下标算 —— 顺序变化也不会开错图。

## 4. 顶栏搜索闪退（已定位到具体代码行）
你这次给的栈非常关键，我用自己的 1.1.2 混淆映射精确还原了：

```
AndroidUiDispatcher.doFrame → Recomposer.performRecompose → CompositionImpl.recompose
 → ComposerImpl.recompose$runtime_release → doCompose → end()   ← 崩在这里
    → androidx.compose.runtime.Stack.pop()  （Stack 继承 ArrayList，空栈 remove(-1) 抛异常）
```

根因：**在 composable lambda 里提前 `return`**。搜索页原来写的是
`if (loading) { LoadingBox(); return@Column }` —— 先 emit 了内容再 return，Compose 的「组结构」就失衡了，
退组时把空栈弹爆。已改成 `when` 分支（不提前返回），用户空间页同样改掉。
全工程已无 `return@Column` 这类写法。

## 5. 消息功能提示「需要登录」
根因：启动时活动账号是**异步恢复**的，消息页抢在恢复完成前判断 `activeAccount == null`，
于是显示「当前是游客模式」。修复：
- `AuthRepository.restoreFromStorage()` + `awaitActiveAccount()`：页面读取账号前等恢复完成（最多 3 秒），并加了恢复闸门，避免重复恢复；
- 消息页、私信页加载前都会先等账号就绪。

## 6. 签到防重复 + 账号名读取
- **防重复**（重点，避免账号异常风控）：`autoSignOnOpen()` 三重判断——
  1. 本地 `sign_records` 今天已经成功过 → 跳过；
  2. 账号自己的 `lastSignedAt` 就是今天 → 跳过；
  3. 签到页面上写着「今日已签」→ 直接返回「今日已签到」，**不提交任何请求**（`signOne` 先读页面再决定是否提交）；
  另外同一进程内 10 分钟节流，防止页面来回切时反复请求。
- **账号名读取**：对齐原项目 `ForumParser.parseUserProfile` 的选择器优先级
  （`.comiis_space_tx h2` → `.username` → `.user_name` → `h1` → `.profile_name`），
  并在入库前做清洗：去掉「xxx 的个人资料 / 的空间 / - MT论坛」这类后缀、识别「欢迎您回来，xxx」，
  仍然拒绝「论坛 / 登录 / 注册 / 纯数字」等噪声。

## 7. 添加账号重做
- **新增「账号密码登录」**（推荐）：App 内直接填账号密码登录 —— 自动过站点 `acw_sc__v2` 人机校验、
  拉登录页拿 formhash/loginhash、POST 登录、再**回个人页确认真实身份**（uid/用户名/用户组/积分）后入库；
  可勾选 **记住密码**（Android KeyStore AES-GCM 加密存本机），后续 Cookie 失效可静默重登、也能参与自动签到。
- **保留网页登录**与 **Cookie 导入**作为备用方式；站点弹图形验证码时走网页登录即可。
- **去掉重复按钮**：页面上那两个白底「添加账号 / 用 Cookie 添加」**已删除**，只保留顶栏一个 `+`，
  点开是「账号密码登录 / 网页登录 / Cookie 导入」三种方式的选择。
- **布局整理**：顶部换成一行紧凑 chip（一键签到 · 签到记录 · 添加账号），下面是说明 + 账号卡片列表。
- 一键签到按钮也改成「先检测今日是否已签，只签没签的」。

## 8. 打开 App 自动签到（先检测是否已签）
- 启动时（`MTLuntanApp`）在恢复账号后调用 `autoSignOnOpen()`：**只对今天还没签到的账号**发起签到，
  已经签过的直接跳过（本地记录 + 账号时间戳 + 站点页面三重确认），多账号按设置里的间隔依次进行；
- 进「我的」页 / 账号管理页手动刷新时也会走同一条逻辑；
- 通知里会写明「成功 N / 今日已签 M / 失败 K」。

## 9. 自动回复解锁：从 AI 分组里拿出来 + 真正修好
- **分组**：设置页新增独立分组 **「自动回复解锁」**（进帖自动解锁 / 后台自动回复 / 每日上限 / 解锁回复内容），
  AI 相关（接口、Key、模型、系统提示词）单独归到「AI」分组；AI 配置页里那组开关也去掉了，只留「解锁回复的内容」并注明开关在设置里。
- **为什么之前不生效**（对照 Java 版 `AutoReplyEngine.sendUnlockReply` 找到三处差异，全部修掉）：
  1. 回复请求**没带 Referer**，URL 参数也不全 → 现在按 Java 版补齐
     `forum.php?mod=post&action=reply&fid=..&tid=..&extra=&replysubmit=yes&mobile=2&handlekey=fastpost&loc=1&inajax=1`
     ＋ `Referer: 帖子页` ＋ `posttime`，Discuz 不再把请求当机器人拒掉；
  2. 以前要求「自动回复」和「进帖自动解锁」**两个开关都为真**才动手 → 现在只看「进帖自动解锁」，
     并且它**默认开启**，打开即生效（后台扫描另有总开关，互不牵连）；
  3. `fid` 解析不到就直接放弃 → 现在从页面里兜底抠 `action=reply&fid=` / 版块链接的 fid；
  另外「用 AI 生成回复内容」需要配好 Key 才会走 AI，否则用固定模板（不配 AI 也能解锁）。

## 10. 侧边栏「没用到时太明显、突出来」
`ModalDrawerSheet` 外面套了 `padding(10.dp)`，抽屉收回后仍有一条边露在屏幕外。现在：
- **去掉外层 padding**，抽屉宽度限制到 300dp 以内，圆角只做右侧；
- 收回后完全离开屏幕，不再有突出的边。
